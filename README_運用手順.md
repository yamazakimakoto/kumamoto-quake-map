# 令和8年熊本地震 被災状況マップ v2 ── 運用手順書

**本体**：`kumamoto_quake_map.html`（ブラウザで開くだけで動作）＋`data.js`（手動更新データ）
**目的**：状況を継続的に追える「使える」災害情報マップ。①地震はリアルタイム（気象庁自動取得）、②その他レイヤーは1日1〜2回の手動更新で運用。

## 2. 更新のやり方（1回5〜15分）

1. `data.js` をテキストエディタで開く
2. 上の表のデータ元を巡回し、**新しい確定情報**を該当配列に追記（既存項目の更新は desc/asof を書き換え）
   ```js
   {name:"◯◯避難所", lat:32.xxx, lng:130.xxx,
    desc:"開設中・約120人（毛布不足の報あり）",
    status:"official",            // ← 確認状態（下記③）
    src:"熊本県防災HP", asof:"7/30 09:00"},
   ```
   - 緯度経度は Google マップ等で右クリック→座標コピー（役場・施設の概略でよい）
3. 冒頭の `LAST_UPDATED` を現在時刻に書き換え
4. ブラウザでマップを再読み込みして表示確認（ポップアップの文字化け・位置ずれがないか）

> 💡 Claude Code に「data.js の避難所レイヤーを最新情報で更新して」と頼めば、収集→検証→追記まで代行できます（本手順書の検証フローを適用）。

## 3. ファクトチェック・フロー（掲載前に必ず）

**status の付け方**：
- `official`（緑）＝気象庁・官邸・省庁・県・市町村・事業者公式の発表で確認
- `media`（青）＝**報道2社以上**で一致確認
- `media1`（黄）＝報道1社のみ（続報で official/media へ昇格 or 削除）
- `unverified`（灰）＝SNS等のみ。**位置・内容の現地確認なし**——地図には載せるが「行動の根拠にしない」旨が常時表示される

**手順**：
1. 一次ソース（発表元）を必ず開いて確認する。**検索結果の要約・スニペットを出典にしない**（当プロジェクト規範）
2. SNS発の情報は、①投稿日時が今回の災害か（旧災害の映像流用が頻出）②位置が特定できるか③複数の独立した投稿があるか、を確認。満たさなければ `unverified`
3. すべての項目に **src（出典）と asof（時点）** を必ず入れる。入れられない情報は掲載しない
4. 誤りと判明した項目は**削除せず** desc を「【訂正】〜」に書き換えて1日残し、その後削除（訂正の透明性）
5. 被害者個人が特定される情報（住所番地・氏名・車両ナンバー等）は掲載しない

## 4. リアルタイム性の現状と拡張余地

- **いま自動**：①地震活動（気象庁 list.json をページ読込ごとに取得・震度3以上・熊本周辺を抽出表示。取得失敗時は保存データに自動フォールバック）
- **手動運用**：②〜⑫（各機関がAPIを提供していないため。定時更新で運用）
- **拡張したくなったら**（Claude Code に依頼可能）：
  - ページに5分ごとの自動再取得（setInterval）を追加
  - 停電情報など定型ページのスクレイピング→data.js 自動生成スクリプト（`update_data.py`）
  - GitHub Pages 公開＋GitHub Actions で1時間ごと自動更新（safety-map と同じ公開フロー）

---

## 5. 公開する場合の注意

- 本マップは現状**ローカル参照用**。一般公開する場合は、①「シミュレーション用・公式情報優先」の免責を維持、②unverified 情報の公開可否を再検討（原則非表示に切替）、③自治体の避難情報への直リンクを冒頭に置く
- 公開先候補：GitHub Pages（hitotsu-tax-sim と同じ手順で `gh` から公開可能）
